# Реєстрація та обмеження доступу

## Як працює реєстрація

1. Користувач реєструється через `/Account/Register`.
2. Пароль зберігається як PBKDF2-хеш із випадковою сіллю (існуючий механізм `UserService`).
3. Новий запис створюється з `IsAdmin = false` та `IsRegistrationConfirmed = false`.
4. Користувач може увійти, переглядати каталог, виконавців і жанри, але не може створювати, редагувати чи видаляти їх.
5. Після підтвердження адміністратором `IsRegistrationConfirmed` встановлюється в `true`. Потрібно вийти та увійти знову, щоб оновилися claims авторизаційної cookie.

## Перший адміністратор

Оскільки ще немає Web API для адміністрування, першого адміністратора потрібно призначити вручну:

1. Зареєструйте обліковий запис через форму реєстрації.
2. Відкрийте SQL Server Management Studio та підключіться до бази порталу.
3. Виконайте скрипт `bootstrap-admin.sql`, замінивши `admin_username` на логін зареєстрованого користувача.
4. Вийдіть із порталу та увійдіть знову.

Не додавайте можливість самостійно виставляти `IsAdmin` у публічну форму реєстрації.

## База даних

У поточній моделі `User` та початковій EF Core migration поле `IsRegistrationConfirmed` уже існує. Тому окрема migration для цього оновлення не потрібна.
